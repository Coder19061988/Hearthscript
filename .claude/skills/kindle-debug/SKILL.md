# Налагодження Kindlescript

Без відтворення й першопричини не виправляй. Між кодом гравця й екраном лежить багато шарів: Python гравця, прелюдія, нативні функції, співпрограми, світ, GDExtension, GDScript. Симптом часто з'являється далеко від причини, а латка на симптом зазвичай ламає сусідній сценарій.

## 1. Відтвори якомога нижче

Від найдешевшого способу до найдорожчого:
1. **Сценарний тест:** `./build/RelWithDebInfo/kindle_proto.exe test <назва>`. У разі провалу друкує весь журнал подій.
2. **Скрипт гравця:** `kindle_proto.exe run <скрипт.py> --days N --chars N --seed N --no-rain`. Друкує журнал подій. Погода залежить від seed, тож фіксуй seed, а непотрібний дощ вимикай.
3. **Godot без вікна:** `D:\Godot4\Godot_v4.6.2-stable_win64_console.exe --headless --path godot --script res://tests/smoke_test.gd`. Провали видно в рядках `FAIL:`.
4. **Godot у вікні з консоллю:** `D:\Godot4\Godot_v4.6.2-stable_win64_console.exe --path godot`. Помилки GDScript і `printerr` видно в терміналі.

Баг, видимий лише в грі, спробуй відтворити сценарним тестом, бо гра працює на тому самому ядрі. Тест-відтворення потім лишається регресійним (скіл kindle-test).

## 2. Збери докази

- **Журнал подій.** Запис `LogKind::Error` тримає повний traceback у `LogEntry::detail`. `format_entry` його не друкує, тож тимчасово виведи `e.detail` через `ctx.info`.
- **Стан.** Дивись `s.runtime().state(id)`, `w.character(id)`, `w.current_action(id)` і `s.runtime().current_line(id)`.
- **Код гравця.** `notify(f"...")` і `print(...)` пишуть у журнал; `print` дає запис `LogKind::Print`.
- **Час.** Кожен персонаж має власний `local_time`, і в межах тіку персонажі йдуть незалежно. Порівнюй події за часом у журналі, а не за порядком викликів.
- **Порівняння з робочою версією.** Користуйся `git diff HEAD -- <файл>` і `git show HEAD:<файл>`. Не роби stash, checkout чи reset: у робочому дереві часто лежать незакомічені зміни користувача.

## 3. Перевір відомі пастки

| Симптом | Імовірна причина |
|---|---|
| Краш або сміттєві значення після дії чи `yield` | Python-об'єкт у C-змінній пережив дію; `py_retval()` передано як аргумент; перед відновленням співпрограми не викликано `py_switchvm(agent->vm)` |
| Гравець отримує RuntimeError замість власного винятку | класу немає в прелюдії або в `__all__`: `raise_action_error` шукає клас у builtins |
| Помилка доступу до `e.reason` чи атрибута винятку | у винятків pocketpy немає `__dict__`; дані лежать в args через `_ErrorInfo` |
| `TypeError` про нехешований тип | `None` став ключем словника: у pocketpy він нехешований |
| Зміни в prelude.py не діють | прелюдія вшита в бінарник, треба перезібрати |
| Гра не бачить нового балансу чи стартового коду | Godot читає копії з godot/data, їх оновлює `./build.ps1`; копії не редагуй |
| DLL не оновлюється або копіювання падає | запущена гра тримає godot/bin/kindlescript.dll; закрий гру, редактор із hot reload можна лишити |
| Маркер рядка зсунутий, у редакторі зайві символи | CRLF: CodeEdit тримає лише LF, нормалізуй `replace(String.chr(13), "")` |
| Краш Godot зі стеком у співпрограмі | Godot API викликано з колбека ядра (`World::on_log`); там можна лише ставити дані в чергу |
| signal 11 під час першого імпорту проєкту | відома проблема Godot 4.6.2 + godot-cpp 10.0.0; повторний імпорт працює |
| Помилка створення VM при великій кількості персонажів | ліміт — 127 персонажів (`PK_MAX_VM_COUNT - 1`) |
| Персонаж «не бачить» запасів, кількості нульові | обмежене знання: він бачить об'єкт лише поруч, тож спершу потрібна дія біля об'єкта |
| `while True: pass` вішає гру | зламався патч трасування pocketpy; див. third_party/pocketpy/PATCHES.md |

## 4. Одна гіпотеза за раз

Сформулюй гіпотезу у формі «X, бо Y», зміни одну річ і перевір. Якщо три виправлення поспіль не допомогли, зупинись. Перечитай розділ «Архітектура» в CLAUDE.md і перевір своє розуміння, а не додавай четверту латку.

## 5. Виправлення

1. Тест відтворює баг і падає.
2. Виправлено першопричину, а не симптом.
3. Тест проходить, і весь набір теж (скіл kindle-verify).
4. У звіті є причина, механізм, зміни й перевірка.
5. Якщо знайдено нову пастку, якої немає в CLAUDE.md, додай її в розділ «Підводні камені».
