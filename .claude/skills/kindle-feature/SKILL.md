# Зміна гри Kindlescript

Зміна в цій грі майже завжди проходить кілька шарів: ядро C++, Python-API гравця, збереження, Godot і документи. Найчастіші помилки тут не в логіці, а в пропущеному шарі: дія працює, але зникає після завантаження; виняток є в ядрі, але гравець бачить RuntimeError; документ описує стару назву. Цей скіл задає порядок і показує, де що лежить.

## Порядок

1. **З'ясуй, що міняється для гравця.** Прочитай потрібні розділи [План_гри.md], [MVP.md] (§8 — що відкладено), [API_прототипу.md], [API_MVP.md].
   - Технічні рішення приймай сам.
   - Користувача питай лише про продукт: що гравець бачить і пише, як це відчувається в балансі, чи входить у поточний обсяг.
   - Якщо відповідь не змінює результату, обери розумний варіант і назви його у звіті.
2. **Онови специфікацію.** Для API це API_прототипу.md або API_MVP.md: назва, параметри, тривалість, винятки, що повертає. Для чисел це Баланс_прототипу.md. Документи — джерело правди, а код і тести їх реалізують.
3. **Напиши тест, що падає**, за скілом kindle-test.
4. **Реалізуй знизу вгору** за картою шарів нижче: ядро → прелюдія → збереження → GDExtension → Godot.
5. **Перевір і звітуй** за скілом kindle-verify.

Невелика зміна, як-от властивість, підпис чи кнопка, окремого плану не потребує. Пройди ті самі кроки коротко.

## Карта шарів

| Шар | Файли | Коли зачіпати | Деталі |
|---|---|---|---|
| Ядро | core/world.h, core/world.cpp | нова дія, стан, правило світу | references/action.md, references/state.md |
| Баланс | core/balance.h, core/balance.cpp, config/balance.json | будь-яке число, яке відчуває гравець | скіл kindle-balance |
| Рантайм | core/runtime.cpp | нативна функція `_kn.*`, новий параметр дії, нова подія для `@on` | references/api.md |
| Прелюдія | core/prelude.py | усе, що пише гравець | references/api.md |
| Збереження | core/save.cpp | кожне нове поле стану | references/state.md |
| GDExtension | gdextension/kindle_simulation.cpp, .h | дані для інтерфейсу, команди гравця з інтерфейсу | references/state.md |
| Godot | godot/scripts/*.gd | показ і керування | references/ui.md |
| Документи | API_*.md, Баланс_прототипу.md, godot/scripts/help_text.gd, CLAUDE.md | зміна API, механіки чи архітектури | references/api.md |
| Тести | proto/tests.cpp, proto/tests_mvp.inc, godot/tests/*.gd | завжди | скіл kindle-test |

Типові поєднання:
- **Нова дія `me.x(...)`:** action.md, потім api.md, потім підписи з ui.md і тест.
- **Нова будівля чи ресурс:** state.md, потім api.md і ui.md.
- **Лише інтерфейс:** ui.md.

## Загальні правила

- **Логіка гри живе лише в ядрі.** Godot тільки показує світ і передає команди гравця. Якщо інтерфейсу бракує даних, віддай їх із ядра через KindleSimulation.
- **Автоматичної поведінки немає.** Персонаж робить лише те, що написано в коді гравця. Не додавай поведінки «за замовчуванням», яка виконує роботу замість гравця.
- **Тексти для гравця пиши українською.** Повідомлення має підказувати, як виправити ситуацію. Не вживай родових форм дієслів про персонажів: «Смерть персонажа «X»», а не «помер/померла».
- **Згенероване не редагуй.** godot/data, godot/bin, godot/.godot і build створює збірка.
- **Бережи незакомічене.** У робочому дереві часто лежать незакомічені зміни користувача. Не роби stash, checkout чи reset, а коміть лише на прохання.
