# Зміна Python-API гравця

Гравець бачить API у чотирьох місцях. Прелюдія визначає, що реально працює. Документи — специфікація. Довідка F1 і підсвічування — те, що гравець бачить у грі. Розбіжність між ними найлегше заплутує гравця, тому всі чотири змінюються разом.

## Перед кодом

- Прочитай загальні правила (§0), винятки (§6) і уточнення семантики (§10) в API_прототипу.md, а також потрібний розділ API_MVP.md.
- Тримайся наявного стилю назв:
  - дія — дієслово в snake_case: `me.chop_wood`;
  - властивість — іменник: `house.firewood`;
  - тривала дія приймає обмеження `amount=`, `until=` і `hours=`.
- Спершу опиши зміну в документі, потім напиши тест.

## Що змінити

| Що | Де |
|---|---|
| Python-обгортка | core/prelude.py: метод `Me`, властивість класу будівлі або глобальна функція; докстрінг українською |
| Нове публічне ім'я | список `__all__` у кінці core/prelude.py, інакше ім'я не потрапить у builtins |
| Читання стану світу | нативна функція в `RuntimeNatives` і `py_bindfunc(kn, ...)` у core/runtime.cpp |
| Нова дія | ядро, див. action.md |
| Новий виняток | клас-нащадок `ActionError` у прелюдії плюс `__all__`; ядро кидає його через `fail("<Клас>", ...)` |
| Підписи дії | `ACTION_NAMES` у godot/scripts/game_ui.gd і `ACTION_SHORT` у godot/scripts/world_view.gd |
| Довідка F1 | godot/scripts/help_text.gd, у тематичному блоці |
| Підсвічування | список `API` у godot/scripts/python_highlighter.gd для нових глобальних імен |
| Приклади | приклади в документах; scripts/woodcutter.py, scripts/start_shared.py, scripts/mvp/shared.py, scripts/api_example.py; код у godot/tests/*.gd |
| Пісочниця | новий модуль чи вбудована функція потребують розширеного тесту `sandbox` |

Якщо класу винятку немає в builtins, `raise_action_error` у core/runtime.cpp тихо підмінить його на RuntimeError. Тоді `except NoItemError` у коді гравця не спрацює.

## Перейменування

- Шукай стару назву по всьому репозиторію, крім third_party і build. Перевір і Python-код у C++-рядках `R"PY(...)PY"`, і GDScript-тести.
- Збереження містять код гравця як текст. Старий код після перейменування впаде з AttributeError, тож скажи про це користувачу.

## Правила прелюдії

- Перевіряй аргументи в Python до виклику `_kn.act(...)`. Кидай TypeError чи ValueError з українським повідомленням, яке показує правильний виклик (див. `_limits` і `_id_of`).
- Рядки прелюдії не рахуються як «роздуми» персонажа. Тому допоміжну логіку краще класти туди, а не вимагати від гравця.
- Прелюдія вшита в бінарник, тож після змін потрібна перезбірка.
- Пастки pocketpy описані в CLAUDE.md, розділ «Підводні камені»:
  - у винятків немає `__dict__`;
  - `None` нехешований;
  - Python-об'єкти не можна тримати в C-змінних між діями.

## Нова подія для `@on`

Події дощу йдуть так: `World::begin_tick` повертає рядки `"RAIN"` чи `"RAIN_STOPPED"`. `Simulation::tick` передає їх у `ScriptRuntime::post_event`, а той ставить обробники в чергу. Нова подія потребує:
- значення в класі `Event` і в кортежі `_EVENTS` у прелюдії, інакше `on(...)` її не прийме;
- рядка, який повертає `World::begin_tick` у core/world.cpp.

Опиши подію в API_прототипу.md §5 і в довідці F1.
