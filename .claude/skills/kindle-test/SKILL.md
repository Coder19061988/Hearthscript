# Сценарний тест Kindlescript

Сценарний тест — функція C++. Вона будує маленький світ, дає персонажам Python-код і перевіряє наслідки через ігровий час. Це головний спосіб перевірити ядро, а шар Godot перевіряє окремий смоук-тест.

## Порядок

1. **Спершу тест, потім код.** Напиши тест бажаної поведінки й переконайся, що він падає з очікуваної причини. Тест, який проходить ще до змін, нічого не доводить. Для бага тест має відтворювати баг.
2. **Обери файл.**
   - proto/tests.cpp — технічний прототип (MVP §7) і темп (Баланс_прототипу.md §6).
   - proto/tests_mvp.inc — механіки MVP і новіші: пори року, тепло, поле, будівництво, правила, знання, дошка. Файл включається в анонімний простір імен tests.cpp, тож бачить усі допоміжні функції.

   Став тест поруч зі спорідненими, під коментарем-розділювачем `// ---...--- <тема>`.
3. **Напиши функцію** `void t_<назва>(Ctx& ctx)` за каркасом нижче.
4. **Зареєструй у двох місцях.** Без першого `kindle_proto` тесту не знає, без другого ctest його не запускає.
   - Рядок `{"<назва>", "<опис українською>", t_<назва>},` у `kTests` наприкінці proto/tests.cpp.
   - `<назва>` у `set(KINDLE_TESTS ...)` у CMakeLists.txt, у тому ж порядку.
5. **Збери й запусти** один тест, а після змін коду — увесь набір за скілом kindle-verify.

## Каркас

```cpp
void t_example(Ctx& ctx) {
    Opts o;            // типово: 1 персонаж, 1 сокира, 10 хліба, 200 дерев, день 1, 05:30, без дощу, seed 1
    o.chars = 2;
    Simulation& s = ctx.sim(o);
    World& w = s.world();
    int hero = w.char_obj_id(0);
    s.runtime().set_code(hero, R"PY(
storage = get("Склад_1")
me.take(Axe, storage)
n = me.chop_wood(get("Ліс_1"), amount=2)
assert n == 2, n
notify("приклад ok")
)PY");
    s.run_until(at(1, 12));  // день 1, 12:00
    ctx.check(find_log(w, "приклад ok").has_value(), "скрипт дійшов до кінця");
    ctx.check(count_kind(w, LogKind::Error) == 0, "немає необроблених винятків");
}
```

Головний прийом — `assert` у Python і маркер `notify(...)` наприкінці. Невдалий `assert` стає необробленим винятком із записом `LogKind::Error`, маркер не з'являється, і тест падає. Під час провалу тест друкує журнал подій, де видно точний рядок і значення з `assert`.

## Довідка

| Що | Як |
|---|---|
| Світ | `ctx.sim(Opts)`; поля Opts: `chars`, `axes`, `sickles`, `bread`, `grain`, `wood`, `trees`, `start_day`, `start_hour`, `random_rain`, `seed`. Баланс читається з config/balance.json |
| Стартова сцена гри | `mvp_opts()` — та сама, що `START_OPTIONS` у godot/scripts/main.gd: 4 персонажі, дощ, seed 3 |
| Еталонне поселення | `set_settlement_code(ctx, s)` — scripts/mvp/shared.py і рядок ролі для кожного персонажа |
| Об'єкти сцени | Склад_1, Будинок_1, Ліс_1, Поле_1, Дошка_1; персонажі Остап, Марта, Богдан, Ярина... (core/simulation.cpp) |
| Час | `at(день, год, хв)`; `s.run_until(t[, крок])`; `s.tick(60)` у циклі, щоб стежити за мінімумами |
| Перевірки | `ctx.check(умова, "твердження українською")` — провал без зупинки; `ctx.info(...)` — друк чисел |
| Журнал | `find_log`, `count_log`, `count_kind`, `logs_of(w, obj, needle)`, `time_in(e, від, до)` |
| Стан | `obj(w, "Склад_1")`, `w.character(id)`, `s.runtime().state(id)`, `w.current_action(id)` |
| Код із файлу | `load_script(ctx, "scripts/....py", out)` |
| Сценарій | `w.add_rain(від, до)` — дощ; `w.add_blueprint(ObjKind::House, "Будинок_2", {60, 100}, err)` — креслення; `s.runtime().set_shared_code(code, false)`; `s.runtime().set_global(name, value, err)` |
| Очікуваний виняток | допоміжна `expect(fn, exc, label)` у тесті `mvp_rules` |

## Що варто знати

- **Обмежене знання.** На старті персонаж знає лише свій будинок. Склад, поле й інших персонажів він бачить тільки поруч. Тож перед `storage.amount(...)` у тестовому коді має бути дія біля складу.
- **Незалежний час персонажів.** У межах тіку кожен персонаж іде своїм `local_time`. Тому перевіряй результат після `run_until` із запасом часу, а не впритул.
- **Діапазони замість точних чисел.** У темпових і балансових перевірках задавай діапазон і друкуй фактичні числа через `ctx.info`. Тоді зміна балансу не вимагає переписувати тест, а вивід показує, наскільки змістилися числа.
- **Детермінізм.** Без `random_rain` і з фіксованим seed тест детермінований. Дощ задавай явно через `w.add_rain`.
- **Python у рядку.** Код у `R"PY(...)PY"` пишеться з першої колонки. MSVC компілює з `/utf-8`, тож українські рядки працюють.
- **Тексти.** Назва тесту в `kTests` і повідомлення `ctx.check` — українською, у формі твердження, без родових форм дієслів про персонажів.

## Запуск

```powershell
./build.ps1 -Target kindle_proto                          # швидка збірка лише прототипу
./build/RelWithDebInfo/kindle_proto.exe test <назва>       # у разі провалу друкує журнал подій
./build/RelWithDebInfo/kindle_proto.exe list
./build.ps1 -Test -Filter <назва>                          # через ctest: заодно перевіряє реєстрацію в CMakeLists.txt
python .claude/skills/kindle-verify/scripts/check_sync.py  # kTests і KINDLE_TESTS збігаються
```

Для GDScript-тестів шару Godot дивись references/ui.md у скілі kindle-feature.
