# Kindlescript — MVP (мінімальна версія гри)

## Мета MVP

Довести головну ідею гри: **гравець пише Python-код, і поселення живе або гине через цей код.** Усе, що не потрібне для перевірки цієї ідеї, переноситься в наступні версії (див. «План гри»).

**Критерій успіху:** гравець, який пише хороший код, переживає першу зиму. Гравець із помилками в коді бачить у журналі подій, хто і чому помер, виправляє код і пробує ще раз.

## 1. Код (входить майже повністю)

* Python-код для кожного персонажа та глобальний скрипт для всіх.
* Витрати часу на дії; обмеження тривалих дій часом або обсягом (`until=`, `hours=`, `amount=`); незавершений прогрес зберігається.
* Очікування `wait_until` (з тайм-аутом).
* Невдалі дії викидають винятки (`NoItemError`, `ReservedError`, `TooHeavyError`, `ToolBrokenError`, `WorkplaceBusyError`); необроблений виняток зупиняє код персонажа й потрапляє в журнал подій.
* Обробники подій `@on(...)` / `on(...)` з пріоритетом — 1–2 події для перевірки переривань (наприклад, злива: персонаж перериває роботу надворі й іде додому). Після обробника персонаж повертається до перерваної дії.
* Назви об'єктів і доступ через `get(...)`; назви не змінюються.
* Пошук через `buildings(...)`, `tools(...)`, `me.travel_time(...)` та стандартні `min` / `max`.
* Власні сповіщення `notify(...)`.
* Час на «роздуми»: порожній цикл не вішає гру, а персонаж стоїть без діла.
* Зміна коду на ходу: персонаж перериває поточну дію й починає новий код спочатку.
* Глобальні змінні (змінює лише гравець).

## 2. Світ

* День і ніч.
* Дві пори року: тепла та зима (взимку холодно, поле не росте).
* Невелика карта з лісом і місцем під поле (випадкова генерація — не обов'язкова для MVP).
* Пауза, звичайна швидкість та прискорення часу.

## 3. Люди

* 4 дорослих персонажі; без старіння, народження та міграції.
* Параметри: голод, втома, тепло, здоров'я. Якщо щось пустити на самоплив — персонаж хворіє, а потім помирає.
* Автоматичної поведінки немає: їжа, сон, опалення — лише через код.
* Слоти: одяг (звичайний і теплий), інструмент.

## 4. Ресурси та ланцюжки (лише два)

* **Тепло:** дерево → сокира → дрова → опалення будинку.
* **Їжа:** поле → зерно → ручні жорна → борошно → піч у будинку → хліб.

## 5. Будівлі

* Будинок (піч, ліжко, скриня, опалення).
* Склад.
* Поле.
* Будівництво: креслення на карті з назвою → персонажі приносять матеріали → `me.build(...)`.
* Заселення через код: `me.move_into(...)`.

## 6. Інтерфейс

* Простий low-poly або тимчасова графіка.
* Редактор коду в бічній панелі.
* Камера: огляд поселення згори і прогулянка від першої особи (V) — невидимий спостерігач, на гру не впливає.
* Клік на персонажа показує поточний рядок коду, дію та стан.
* Журнал подій.
* Базова довідка за F1.

## 7. Що перевіряє MVP технічно

Найризикованіша частина проєкту — виконання коду гравця. Прототип має довести, що Python-код гравця:

* виконується безпечно (без доступу до файлів і системи);
* «засинає» на кожній дії, поки йде ігровий час;
* може бути перерваний подією `@on` і продовжений з того самого місця;
* коректно перезапускається, коли гравець змінив код;
* працює для кількох персонажів одночасно без падіння продуктивності.

Від того, як це вирішиться, залежить і вибір рушія.

### Обране рішення: pocketpy

* **Інтерпретатор:** pocketpy — легкий вбудовуваний інтерпретатор Python 3.x для ігрових скриптів (є інтеграції з Godot та Unity).
* **Безпека:** гра сама визначає, які функції та модулі доступні в скриптах; доступу до файлів, мережі та системи немає.
* **Механізм виконання:** код кожного персонажа працює як співпрограма. Кожен виклик ігрового методу (`me.feed`, `me.mow`, `me.sleep` тощо) — точка паузи: скрипт зупиняється, гра симулює дію протягом потрібного ігрового часу й відновлює скрипт з наступного рядка. Переривання `@on` спрацьовує в тій самій точці: спершу виконується обробник, потім персонаж повертається на перерване місце.
* **Збереження гри:** після завантаження збереження персонажі починають свій код спочатку (прогрес дій зберігається) — так само, як після зміни коду.
* **Запасний план:** якщо на pocketpy не вдасться чисто реалізувати паузу та переривання — власний інтерпретатор підмножини Python (як у грі *The Farmer Was Replaced*).

### Рушій: Godot 4

* **Чому Godot:** безкоштовний і відкритий, легкий для старту, добре підходить для low-poly 3D.
* **Інтеграція pocketpy:** готові доповнення pocketpy для Godot призначені для того, щоб *розробник* писав логіку гри на Python замість GDScript. Нам потрібне інше — ізольоване виконання *коду гравця* з доступом лише до ігрового API, паузами на діях і перериваннями. Тому план такий:
  * логіка самої гри — на GDScript (або C#);
  * код гравця виконується в pocketpy, підключеному через власне невелике GDExtension-розширення (C API pocketpy), яке відкриває скриптам лише ігрове API (`me`, `world`, `get`, `buildings`, винятки тощо) і забороняє імпорти;
  * наявні доповнення godot-pocketpy — як приклад інтеграції та відправна точка.

### Перший технічний прототип

Мінімальний прототип для перевірки рішення:

1. Один персонаж і дві дії: `me.chop_wood(...)` та `me.sleep()`.
2. Хід ігрового часу: кожна дія займає час, після неї `world.time` показує новий час.
3. Обмеження тривалої дії: `until=` і `amount=`.
4. Одна подія `@on` (наприклад, злива), яка перериває дію, і повернення до перерваної дії після обробника.
5. Виняток із дії (`NoItemError`) та запис необробленого винятку в журнал.
6. Зміна коду на ходу → персонаж починає новий код спочатку.
7. Порожній цикл не вішає гру (час на «роздуми»).
8. Навантажувальний тест: 20–50 персонажів із власними скриптами одночасно.

## 9. Приклад коду гравця для MVP

```python
@on(Event.RAIN, priority=1)
def hide_from_rain(me):
    me.go_home()
    me.wait_until(lambda: not world.is_raining)

while True:
    me.wait_until(time(6, 0))
    me.pick_up(get("Склад_1"), "bread", 1)
    me.eat("bread")

    try:
        me.take(Axe)
        me.chop_wood(amount=10)
        me.drop(get("Склад_1"))
    except NoItemError:
        notify("Немає вільної сокири")

    if world.season == Season.WINTER:
        me.wear(WarmClothes)
        me.heat(get("Будинок_1"))

    me.go_home()
    me.sleep()
```
